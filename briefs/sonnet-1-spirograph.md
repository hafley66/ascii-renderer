# sonnet-1-spirograph

Subject: a rolling circle laps a closed hypotrochoid (rolling inside a fixed
ring) or epitrochoid (rolling outside it) track forever, the way a real
Spirograph toy traces a rosette one lap at a time. The seed fixes the fixed
circle radius R, the rolling circle radius r, and which side it rolls on;
those three integers set the lobe count and whether the curve reads as
cusped petals or looping vines.

What moves and why: the fixed circle never moves. The rolling circle orbits
it once every `2*PI` of an angle `theta`, and a pen offset `d` from the
rolling circle's center is what actually draws the curve. `theta` advances at
a constant rate so one full traversal of the closed track (`q` laps, where
`q = r / gcd(R, r)`) takes `BASE_CYCLE / SPEED` seconds -- 36 seconds by
default, so a full pattern always completes in 20 to 60 seconds regardless of
how many laps `q` needs. The comet trail is a sliding window of the last
`TRAIL` fraction of one and a half revolutions behind the pen, so the eye
always has a visible arc chasing a visible gap: the motion is what shows you
the curve is being generated by a wheel rolling on a wheel, not stamped.
A dim full-track echo sits underneath so the whole rosette's shape is legible
even while the comet is only tracing part of it -- that echo is the secondary
element: it turns a live pen trace into a piece with depth (a "was" beneath
the "is"), instead of a bare debug plot of one wheel.

Glyph families:
1. Comet head and near-head: `@`, `#`
2. Comet body fading to tail: `*`, `=`, `:`
3. Full-track echo (very dim, always full circumference): `.`
4. Mechanism: fixed and rolling circle outlines `.`; connecting arm `-`, `|`,
   `\`, `/` (slope-picked) with a `+` joint at the pen
5. Pen spark burst, one of three seed-picked sets: `.` `` ` `` `'`, or
   `*` `:` `+`, or `~` `"` `.`
6. Frame rim `+`, `-`, `|`; label text in plain ASCII

Knobs (registry `param_f32`, positional CLI args in this order):
- SPEED: lap speed multiplier (default 1.0, higher = faster full traversal)
- HUE: hue offset in degrees added to the seed's base hue (default 0)
- DEPTH: pen offset from the rolling circle's center, as a multiple of r;
  above 1.0 the pen sits outside the rolling circle and the curve self
  intersects into loops instead of cusps (default 0.85)
- TRAIL: comet length as a fraction of 1.5 revolutions (default 0.5)
- GLOW: pen spark burst intensity / particle count (default 1.0)
- ARMS: show the fixed circle, rolling circle, and connecting rod, 0 or 1
  (default 1)
- ECHO: brightness of the full-track ghost curve, 0 hides it (default 0.5)
- LABEL: show the "R:r side depth" text readout, 0 or 1 (default 1)
- SCALE: fraction of the available frame the pattern fills (default 0.92)
- MARGIN: cells between the rim and the grid edge (default 1)
- ASPECT: horizontal cell-aspect correction so circles read round (default 2)

Positional order: speed hue depth trail glow arms echo label scale margin
aspect.

Seed-driven choices: R (6..13), r (1..5), and inside/outside pick the
configuration (lobe count and cusp vs. loop shape); the base hue is drawn
from the same per-seed stream; and the spark glyph set (one of three) plus
the arm's solid-vs-dotted line style are the seed-driven secondary-element
variants.

Render commands:
```bash
ASCII_GRID_W=110 ASCII_GRID_H=36 ./target/release/ascii-renderer 7 sonnet-1-spirograph moss | sed 's/\x1b\[[0-9;]*m//g'
ASCII_GRID_W=110 ASCII_GRID_H=36 ASCII_T=12 ./target/release/ascii-renderer 7 sonnet-1-spirograph moss | sed 's/\x1b\[[0-9;]*m//g'
```

The measured layers only add up to about 32% of the sweep's per-frame wall
time here. The mode is a curve trace, not a filled field: every layer
combined costs well under half a millisecond at 2000x1000, so the sweep
harness's own fixed per-frame overhead (grid setup, capture bookkeeping)
dominates the ratio even though every painter in `draw_sonnet_1_spirograph`
is wrapped. `pendulum-wave`'s own worst-case sweep (`ARC=1`) shows the same
pattern at 78.9%: a fast mode's harness overhead is not itself a layer to
account for. Frame time, not layer share, is the hard requirement, and this
mode clears it by more than 20x.
