# Terminal end-to-end regression suite

Headless execution uses the same demo workflow, input assertions, saved presets,
animation controls, resize and terminal-restoration checks through native Rust `portable-pty` and
`vt100`. It does not require a GUI or foreground focus:

```sh
scripts/13_e2e.sh --headless
scripts/13_e2e.sh --headless --function-trace
scripts/13_e2e.sh --headless --mode terminal-stress --case max-400x200
```

The observer checks PTY liveness instead of focus; all existing wall-time, RSS,
disk and observer-heartbeat limits remain active. Terminal-cell snapshots replace
GUI screenshots, and reports explicitly leave GUI painting untested. A Rust reader thread drains the PTY and parses ANSI directly. Python only sends
control requests and reads requested screen snapshots. Cadence includes the native
consumer, and GUI painting remains outside headless coverage. A safety trip stops the suite and marks remaining cases
unrun. Function traces are included in each case's artifact budget.

Run from the repository root on macOS with iTerm2 running:

```sh
scripts/13_e2e.sh
```

Enable **iTerm2 Settings → General → Magic → Enable Python API** once. The suite
uses iTerm's official Python library and macOS Quartz to control and identify a
dedicated window. macOS must permit capture of that window. Keep it focused during
each live case; changing focus stops the workload. The test closes only its own
window and uses a session-local font and isolated app configuration.

The command installs pinned Python dependencies into a temporary virtualenv,
builds the current release binary with the lockfile, tests the watchdog/evidence
reader, and runs the cases below. `samply` must be installed and on PATH. A missing
prerequisite, assertion failure, safety trip, missing profile, or unexecuted case
prevents a full-suite pass. Exit status is nonzero on failure. Existing result
directories are never overwritten.

## Cases

| Case | Workload | Required evidence |
| --- | --- | --- |
| `backpressure` | Actual application and 400×200 PTY; deliberately stop consuming output | Knob application within 250 ms, quit restoring terminal mode within 250 ms, input/relay logs, default periodic frame samples 1/11/21, all-max inputs and dimensions |
| `workflow` | `ascii-renderer 42 demo` in iTerm, 160×40, resize to 180×45 | Search and select gem-aetherium-2, save exact seed/knobs with `s`, start native animation, changing art pixels in PNGs, live knob adjustment, two deterministic random jumps, pause/resume, resize in both frame inputs and visible footer, `q` back to demo, `q` exit, exact termios restoration before watchdog cleanup, profiler samples from animation worker |
| `bad-400x200` | Actual demo in iTerm, 400×200; recorded bad-roll-6 knob values | Exact initial frame inputs, visible art motion, ten frame records, live knob/jump controls, `q` to demo, Ctrl+C exit, terminal restoration, samply profile, cadence gates |
| `max-400x200` | Same demo path, every declared knob at maximum | Same requirements; maxima exported from the current binary rather than copied values |

The fixture's knobs are loaded explicitly with randomization disabled at startup.
This reproduces the recorded **effective values**; it does not claim that the
initial randomization flag or roll counter equals the historical log. Reroll
controls are then exercised through actual keyboard input.

For the large cases, steady frame intervals 2–10 must have p95 ≤ 33.34 ms and max
≤ 100 ms. These are **application frame intervals**. The test captures changing
window pixels and reads iTerm's screen state; it does not measure display scanout
or claim a paint FPS. `samply` sampling is enabled during GUI runs, so its overhead
is part of these instrumented measurements.

Each GUI case launches the app behind `5_probe_guard.py`: 15 s wall time, 256 MiB
owned RSS, 256 MiB shared iTerm RSS growth, 768 MiB shared iTerm absolute RSS,
32 MiB artifacts, and at least 2 GiB free disk. The independent guard also checks
the observer PID and a focus heartbeat which expires after 1.5 s. Limits are
polled and can overshoot. A resource/focus/observer trip stops the owned tree and
prevents later GUI stress cases. The shared iTerm process is never signalled.

The smaller workflow is a functionality case. Passing it does not satisfy either
400×200 performance case. Partial case runs are explicitly marked as partial:

```sh
scripts/13_e2e.sh --case workflow
scripts/13_e2e.sh --case bad-400x200
scripts/13_e2e.sh --case max-400x200
scripts/13_e2e.sh --case backpressure
```

## Artifacts and triage

`perf/results/e2e-<unix-epoch-ms>/report.json` records each case's status, including
`not_run`. Each case preserves its own directory:

- `command.json`, binary SHA-256, commit, dirty-tree status and diff hash.
- `fixture.json`, isolated `config/`, saved presets, exact timestamped keys.
- `animation.ndjson`: seed, palette, knobs, time, roll, grid/terminal dimensions,
  frame generation/encoding/output timings, and parent relay/input telemetry.
- Named screen text assertions, failed screen text, and window PNGs (GUI), or
  native parsed-cell snapshots, compressed ANSI and native-terminal-stats.json (headless).
- `guard.ndjson`, `observer.json`, profiler stderr and app exit state.
- `profile.json.gz` and `profile-summary.json` for GUI cases, including profiles
  saved after a safety stop when samply can finish within its two-second cap.

Inspect a preserved profile with:

```sh
samply load perf/results/<run>/<case>/profile.json.gz
```

The frame logs preserve the exact render inputs for the existing `replay` CLI.
The watchdog's process snapshots and relay wait counters remain available even
when the test cannot reach its first animation frame.

## Current verified failures

During development, the real screen assertion caught an incomplete footer after
resize. Clearing the screen retained the footer/panel caches, so equal prefix
characters were omitted at their new position. The fix invalidates both UI caches
when the frame clears the screen.

The retained 200×60 development run `20_e2e/workflow-attempt7` hit shared iTerm RSS
growth after 3.32 s: 225,296 → 497,344 KiB. This is shared-process growth and does
not identify a specific allocation owner. Its observed knob-to-frame latency was
71 ms. The bounded PTY run `20_e2e/backpressure` measured a knob delay of 1,005 ms,
which failed the 250 ms gate; it applied after the stalled reader resumed. Quit
restored terminal mode in 2.6 ms. These are failing regression evidence, not
passing performance results.
