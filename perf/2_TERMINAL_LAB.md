# Drawing-only terminal lab

```sh
bash scripts/18_terminal_lab.sh
```

`examples/0_terminal_lab.rs` uses Ratatui 0.30.2's ordinary `Terminal::draw`
interface with its Crossterm and Termion backends. The example has no application
mode generation, playback supervisor or per-function instrumentation. It fills a
deterministic cell buffer, lets the library diff and encode it, then submits the
complete frame with `write_all` and `flush`. Synchronized-output markers are
generated by Crossterm. No custom ANSI encoder or terminal parser is used.

Each case renders eight 400x200 frames. Static, sparse, dense monochrome and dense
per-cell color patterns run through both backends and three consumers:

- Memory: library buffer construction, diffing and ANSI encoding.
- PTY drain: identical library path, plus actual PTY output consumed by Pexpect.
- pyte: identical PTY path with terminal-cell interpretation by pyte.

The runner removes `NO_COLOR` for both backends and disables app function tracing.
Each case has the existing external 15-second, 256-MiB and 32-MiB watchdog.
Records retain per-frame fill, library and output times, bytes, command and guard
state. Medians below exclude the first draw. The seven steady frames establish a
bounded comparison, not long-run throughput or GUI painting performance.

## Measured results

`perf/results/29_terminal_lab/results.json`, median total milliseconds per frame:

| Pattern | Crossterm memory | Termion memory | Crossterm PTY drain | Termion PTY drain | Crossterm pyte | Termion pyte |
|---|---:|---:|---:|---:|---:|---:|
| Static | 1.822 | 1.896 | 1.813 | 1.989 | 1.836 | 2.107 |
| Sparse | 2.591 | 1.958 | 4.081 | 4.162 | 32.690 | 36.012 |
| Dense monochrome | 3.183 | 2.406 | 4.900 | 4.018 | 87.142 | 79.921 |
| Dense color | 6.974 | 5.078 | 12.684 | 9.939 | 380.353 | 323.418 |

All 24 cases completed within their guards. Both libraries produced matching
final characters and cell styles for all four patterns (80,000 cells each).
The comparison includes the cost of pyte's consumer in the application's output
waits. Consequently, the earlier pyte-backed headless E2E cadence failures do not
establish the production terminal's animation ceiling. Headless workflow checks
remain useful for state, input, resize and output correctness.

The lab demonstrates sub-16.7-ms frame submission for these synthetic patterns
through a draining PTY. It does not reproduce the full gem-aetherium-2 workload
or measure when iTerm/WezTerm paint a frame. Existing app performance is unresolved.

The example uses Ratatui's `unstable-backend-writer` feature to inspect the encoded
byte buffer for measurement; its version is pinned. The actual drawing uses the
standard `Terminal::draw` API.
