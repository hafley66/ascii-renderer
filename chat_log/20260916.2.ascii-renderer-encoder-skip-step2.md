## Problem/Context
- The encoder paid about 27 ns/cell of fixed scan on every frame regardless of churn
  (1992 us for a completely identical frame at 366x199) because it converted every
  cell unconditionally and then let ratatui diff the whole grid.
- The session's earlier `convert`/`emit` split made this measurable per frame: convert
  is flat at about 19.6 ns/cell whether 72,834 or 39,944 cells changed; emit is what
  responds to churn. That is why step 2's value is in convert, not emit.
- The plan's original design ("write into `current` only for cells whose raw `Cell`
  differs") is right in spirit and insufficient in detail: keeping two ratatui buffers
  consistent while skipping writes has three distinct failure modes, and two of them
  showed up in practice.
- `AnsiFrameEncoder::encode` is called by the morph demo loop and four morph tests,
  `_30_illuminarium` (both its perf test and its headless path) and
  `_52_gem_aetherium_3`; all pass `force_full` false, so full repaints happen only on
  the first frame, on resize, on strategy change, on pause and after an unpresented
  frame.
- Machine policy from the previous session still applies: `nice -n 19 cargo --jobs 2`,
  one build per verification round, E2E only when terminal output changes.

## Solution/Approach
- The landed shape is the third one. Instead of flipping two buffers each frame, keep
  `current` as the authoritative displayed state and `previous` as a reference that is
  only refreshed at the moment a cell changes (`previous[i].clone_from(current[i])`
  before the overwrite, then both sides get the same diff option so `Cell::eq` reduces
  to content). A resting cell costs one shadow compare and one option write and is
  never compared, so a fully resting frame clones nothing, which is where the 6.5x
  comes from.
- Byte identity is the contract: the emitted set is exactly HEAD's, verified at grid
  level (2 modes x 2 sizes x 3 stages) and on a 60-frame sequence (gem totals tuple
  identical to HEAD's).
- Rejected on evidence: the two earlier shapes above; the terminal ceiling (iTerm2
  inline images / Sixel) remains unaddressed and unrequested.

## Key Insights
- `ratatui::buffer::Cell` derives no `PartialEq`: it is a manual `impl` and it compares
  `symbol`, `underline_color`, the deprecated `skip`, `fg`, `bg`, `modifier` and
  `diff_option`. Two cells with identical content and different diff options are
  unequal, which is what produced a 79 percent byte blowup in the first rejected
  revision and what makes option bookkeeping part of correctness rather than
  bookkeeping.
- `CellDiffOption::Skip` is honored before the comparison in `BufferDiff::next`, so a
  skipped cell is neither compared nor emitted; `AlwaysUpdate` bypasses the equality
  check entirely. Cells with no symbol count as equal to a single space.
- `AnsiFrameEncoder`'s two buffers hold values from frames N and N-2 alternately while
  a flip is in use; any scheme that skips writes into one of them has to reason about
  which frame each hole belongs to. Removing the flip removes the whole class.
- `encode`'s `bytes` field is `output.len()` after the UTF-8 copy, so byte identity
  between revisions is directly observable from the probe without diffing payloads.
- The probe's medians are 15 to 40 percent below the plan's section 1 reconnaissance
  numbers because section 1 measured once per size on a loaded host; the encoder rows
  are stable run to run, render is not. Two revisions compared through alternating runs
  of two binaries in one session is the protocol that survives host load, and the test
  binary's file name hash is metadata-based, so it must be copied out before a rebuild.
- `scripts/13_e2e.sh` takes about 4.5 minutes for one case and refuses to run under a
  probe guard that watches owned RSS, wall time and artifact size; it passed 9/9 with
  no changes to its limits.
