## Solution/Approach
prismata design: field = (form, channel) per cell in a reusable thread-local scratch; per-frame color LUTs (8x32 fg, 8x32 bg, 8 block bg); per-cell phase evaluation uses a 4096-entry sine table + libm atan2; the fold maps the plane into `SYMMETRY` wedge sectors (dihedral kaleidoscope) and the field is a function of the folded position; 4 categorical knobs (FORM 0..6, DIALECT 0..4, GLYPHS 0..2, SYMMETRY 1..12) + 8 continuous (FREQ, WARP, DENSITY, CONTRAST, CHROMA, GLOW, FLOW, GRAIN) so `rand_knob` rolls land in whole visual regimes. Two design flaws found and fixed during verification: DENSITY was inert in 3 of 5 dialects (now biases the stored field) and SYMMETRY was mathematically inert on radial rings (now bends each sector's ring phase).

Plan (perf/16_LARGE_RENDER_PLAN.md), ordered by payoff/risk:
0. Promote the throwaway split bench into an ignored env-driven probe (ASCII_SPLIT_MODE/W/H) so every later step is measurable.
1. Row-parallel field + 4 paint passes, gated at w*h >= 65_536 (repo precedent _50_gem_aetherium_2.rs:493-497); expected 2.0ms -> ~0.5ms at 366x199; must stay BIT-IDENTICAL (row-disjoint writes).
2. gridio.rs: keep a raw Vec<Cell> copy and write into ratatui `current` only for changed cells -> kills most of the fixed 27 ns/cell scan (1992us -> ~300-500us at 366x199), byte-identical emission guarded by gem_bad_roll6_ansi_regression exact totals.
3. Buffer hygiene: drop the UTF-8 validate+copy (`push_str(from_utf8(&self.bytes))` gridio.rs:280) and the `insert_str(0, ...)` memmove (morph.rs:1451,1530).
4. Mode-local fold geometry cache across animation frames (fold = 11.3 ns/cell; needs warp moved into folded space; art changes so snapshots re-inspected).
5. Investigation gate on the terminal consumer: measure attribute commands/frame with the user's terminal; do NOT re-propose REP or gap-cost pricing.
Non-goals: never raise probe guard limits; keep serial path below the gate; no new retained simulation state.

## Key Insights
- The mode's render is only ~1/3 of app-side cost and a low single-digit share of the live frame under a GUI terminal; at 400x200 the measured consumer cost was 37.5ms of a 40ms frame. Do not promise live fps gains from render work.
- The encoder pays a fixed ~27 ns/cell scan even when 0 cells change (1992us at 366x199, 0 bytes) — same order as the whole render at that size. This is the highest-value SHARED lever.
- libm atan2f on macOS beat a hand-written 5-term polynomial (20.7 vs 23.1 ns/cell) — measure before optimizing.
- A knob sweep invoked with ASCII_P_* env vars does NOT measure that knob: perf sweep pre-seeds LIVE_PARAMS with `Some(None)`, and param_f32's `Some(value) => value.unwrap_or(default)` branch ignores the env. Two earlier "ablations" were invalid because of this.
- `runs` in FrameEncodeStats counts row-runs (199 = row count on a full frame), not attribute spans.
- `AnsiFrameEncoder::encode(grid, force_full, out)` — the bool is force_full, not "animated"; passing true makes a delta measurement meaningless (all 72,834 cells reported changed).
- insta: CI=true is set in this environment so insta refuses to write .snap.new; run with `env -u CI INSTA_UPDATE=new cargo test ...`, inspect, then `mv *.snap.new *.snap`. Also CARGO_MANIFEST_DIR is polluted from another project — unset it when running insta tests.
- Full-suite baseline: 452 passed, 2 pre-existing failures (gridio ansi encoder RGB-level test, morph gem_bad_roll6_ansi_regression), 15 ignored. `every_native_mode_has_layer_timers` passes with the 5 prismata layers.
